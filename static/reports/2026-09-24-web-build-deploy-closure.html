● 定案 web-build web-deploy

做網站有了固定流程。
建到滿意，才准上線。

以前做網站沒有固定流程：進度只留在對話裡，換對話就要重講；部署前也沒有固定一道檢查，確認內部筆記不會跟著送出去。現在拆成兩支技能：web-build 從問清楚需求做到本機驗收，web-deploy 只負責把驗收過的站送上去，送之前核對產物、再當場問你。

3. 芙莉蓮改壞過什麼，怎麼發現

實跑與 Windows Codex 審查抓到 · 芙莉蓮修
漏 .git/

一開始只防內部筆記資料夾，沒防 Git 歷史。
部署乾跑時用 rsync 列清單，發現 .git/ 有 62 行會被送出去，而 Git 歷史裡就有交接紀錄全文。當場補進排除規則（commit d83b0efc）；但只改了契約檔第二道、漏了第三道，審查第 1 輪才抓到，修在 ca50c29d。

留了後門

「既有站列不出送出清單，就由你決定」這個分支。
審查第 1 輪指出它跟「沒核對產物就不部署」打架：等於沒核對也能上線。整段砍掉，改成用腳本的乾跑或只準備模式列清單，列不出來就不部署、也不進當場授權那一問。

評測寫反

評測案例把「建資料夾」排在「填判準表」之後。
正文與實跑都是「你一選建置流程就先建三樣，再問缺項」，評測卻寫成缺項就什麼都不建，會把正確行為判錯。審查第 2 輪抓到，修在 3d557f49。

實跑抓到

同一站第二次選視覺方向，可能拿舊的選向結果直接往下走。
「既有站加一頁」那條鏈實跑時發現判模式表沒要求「選向紀錄要對得到這次範圍」，補在 14d20ead。

送審前抓到

第 2 輪送審提示詞寫錯受審檔的變動數量。
提示詞說「只有兩個檔變了」，送前用 git 比對發現帳本也多了一行，改成三個檔再送；沒送錯的版本出去。
