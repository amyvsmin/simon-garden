## 定義

付費 AI 操作防線，是在啟動會消耗訂閱額度或產生 API 帳單的自動化工作前，先把「誰付錢、最多可能花多少、能不能中止、怎樣才算完成、敏感產物放哪裡」變成可驗證條件。重點不是只設一個成本數字，而是同時約束計費身分、成本邊界、取消語意、成功條件與資料落點。

## 關鍵面向

- **先確認計費身分**：同一工具可能同時接受訂閱登入與 API key；憑證優先序若不明確，實際帳單可能落到意料之外的帳戶。非互動環境尤其應顯式指定認證來源。
- **軟上限不等於硬停損**：成本上限可能只會停止派發新請求，已在執行中的請求仍會完成；估算金額也可能排除手續費或附加費。標示「上限」前要確認它是 hard cap 還是 soft cap。
- **取消能力決定介面選擇**：若某個傳輸層不能取消正在計費的工作，就不該從該介面啟動長任務；可查狀態不代表適合執行。
- **不完整覆蓋必須 fail-closed**：掃描、稽核或批次處理只完成一部分時，不能以成功碼或「通過」呈現；可保留部分結果，但整體狀態要明確失敗，呼應 [[loud-failure]]。
- **敏感產物與工作目錄隔離**：含原始碼片段、弱點細節、重現步驟或憑證資訊的報告，應落在 repository／worktree 外，並限制存取權限，避免被誤 commit 或同步出去。
- **先做低成本預檢**：正式執行前先用 dry-run、小範圍、單一小型目標或 diff 模式驗證認證、範圍、輸出位置與模型設定，再逐步放大。

## 應用場景

- **Simon 工作場景**：未來評估 Codex Security、Agent SDK、`claude -p` 或其他會計費的自動化時，先檢查計費來源、軟／硬上限、取消方式、失敗碼與輸出隔離，再決定是否授權實跑。
- **CI／排程**：非互動執行不會有人臨場確認憑證或看到半成品，應顯式選認證、限制範圍、把不完整結果視為失敗，並將敏感輸出存到受控暫存區。
- **批次 Agent 任務**：提高併發前先確認單次成本與在途請求的最壞情況，避免「停止派工」被誤解成「帳單立刻停止」。
