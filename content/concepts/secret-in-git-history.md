## 定義

把 API 金鑰、密碼或憑證存進版本控制之後，就算之後刪掉那一行，紀錄仍留在版本歷史裡、也已散佈到每個抓過這份專案的人手上。程式改壞可以還原，金鑰一旦進去只能整把作廢重新申請。

## 關鍵面向

- **跟一般失誤的差別在能不能復原**：版本控制的價值就是「什麼都救得回來」，但這個特性反過來讓金鑰救不掉——你要的是讓它消失，而版本控制的職責正是讓東西不會消失。
- **外洩範圍不等於你按下上傳的那一刻**：只要有人抓過這份專案，那份歷史就在他的硬碟上；就算把雲端上的紀錄清乾淨，也管不到已經散出去的副本。
- **事前的防線只有一道**：在檔案第一次被追蹤之前，用 `.gitignore` 把 `.env`、密碼檔與各種金鑰擋在版本控制之外。事後補救都是損害管制，不是還原。
- **不必自己記哪些檔案該擋**：可以直接請 AI 掃一遍專案，確認環境變數檔、憑證與金鑰都已列入忽略清單。
- **正確的擺法是放在專案之外**：需要長期保存的機敏設定，放在不會被版本控制掃到的位置，程式執行時才去讀。

## 應用場景

- Simon 工作場景：vault 會同步到私有 GitHub，記帳系統與 envelope 的單一真值因此放在 `~/.secrets/` 而不是 repo 內；OpenAI 與 NotebookLM 的金鑰同樣留在機器側。
- 一般場景：ISO 27001 導入時的原始碼與設定管理，以及交接專案給廠商前的清查。
